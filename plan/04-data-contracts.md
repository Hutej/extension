# Data contracts and ownership

**Proposed normative schema design.** Purpose: let implementation agents build exact boundaries without inventing state. Tables describe conceptual schemas, not TypeScript implementation. Every wire record rejects unknown fields unless an explicitly named extensions field exists; v1 has none. Numbers must be finite. Strings have limits from [performance](15-performance.md). All IDs are opaque, bounded strings generated by the runtime/broker, not authority supplied by a model.

## 1. Common records

| Representation | Required conceptual fields | Ownership / lifecycle |
|---|---|---|
| DocumentKey | tabId, frameId, browserDocumentId, runtimeInstanceId | Broker verifies browser sender; new runtimeInstanceId on injection, no reuse after unload |
| Epoch | routeEpoch, domRevision, customizationRevision, viewportRevision | Runtime; increment on relevant invalidation, no wall-clock comparison |
| Envelope | protocolVersion=1, requestId, kind, runId when run-scoped, documentKey when page-scoped, expectedRouteEpoch, deadlineAt, payload | Producer → validated receiver; JSON only. Browser sender metadata is checked separately |
| ErrorRecord | code, phase, retryClass, message, fieldPath?, groupId?, resourceId?, measuredCoverage?, recoveryAction | Explicit unknown/stale/denied/invalid/etc; never raw provider body or page HTML |
| CommandReceipt | requestId, operationId, payloadDigest, status, currentEpoch, resourceIds, error? | Executor owns; repeated same ID+payload returns same receipt; different payload is conflict |

Receipt status: `prepared`, `applied-provisional`, `accepted`, `rolled-back`, `conflicted`, `not-applied`, `outcome-unknown`. An RPC timeout is not `not-applied`.

## 2. Observation model

### PageSnapshot

Required: schemaVersion=1, snapshotId, DocumentKey, Epoch, collectedAt, viewport (CSS width/height, scale if measurable), document metadata (origin, optional redacted title), roots[], regions[], actionCatalog[], customizationSummary[], coverage.

Coverage: visitedNodes, selectedRegions, omittedRegions if known, completed boolean, reason (`node-budget`, `time-budget`, `privacy`, `unsupported-root`, `unstable`), nextCursor or null. No “all page covered” if only a sample was read. A cursor is valid only for its snapshot/route epoch and expires after 30 seconds.

### Region / target evidence

| Field | Contract |
|---|---|
| targetRef | Opaque snapshot-local token; one target or one declared set, never an arbitrary selector echoed by model |
| rootRef, parentRef? | One document or open ShadowRoot; parent relationship only when actually observed |
| kind | `element` or `set` |
| semantics | Declared role/tag/name facts; inferred component/category with provenance and `unknown` possibility |
| name/textSample | Optional capped privacy-filtered content; omit form/editor values and private content by default |
| geometry | Quantized rect and clipping facts, coordinate space explicitly viewport or document |
| styleFacts | Requested/sampled computed values and unsupported-color flags |
| cardinality | Exact observed count, min/max allowed for the target contract; sets list sampled members and count coverage |
| affordances | IDs into actionCatalog, not model-written JS |
| stability | `session-only`, `stable-anchor`, `set-template`, `ambiguous`, with evidence reason |

### TargetDescriptor (persistable intent)

Required: descriptorVersion=1, rootPath[], selection (`single` or `set`), anchor predicates, relative relation, semantic guards, matchBounds, routeScopeRef, continuityPolicy.

- rootPath: each open shadow host described relative to previous root; unique at every hop. Frames are separate DocumentKeys, not selector segments.
- Anchor predicates: observed tag; exact stable ID/test attribute where available; role plus accessible label only if user permits saving that label. Relations: self, descendant within a verified ancestor, direct child, sibling within a verified parent. Positional relation is session-only unless the user selected a set; never durable single-node identity by index alone.
- semantic guards: observed role/control type, required anchor/parent, and optional text discriminator explicitly marked sensitive. Geometry/color is not identity.
- matchBounds: single exactly 1; set explicit maximum 200 per incremental binding pass and total cap 2,000 active members/document. Partial membership is reported, never silently treated as complete.
- continuityPolicy: `session-instance` (exact node only), `stable-single` (re-resolve unique anchor), `future-set` (evaluate every future member against the same approved predicate). Dynamic text-only classification is not automatically generalized to future content.

For a continued resource, saved TargetDescriptor retains its original stable identity predicates, excluding fields intentionally changed by that resource. Do not persist a descriptor requiring the previous transformation's text/style on the original cold page. A rewrite with no independent identity anchor is session-only. See the descriptor-refinement rule in [observation](07-observation-and-targeting.md).

The runtime keeps a separate `ResolvedTarget`: weak node reference(s), root identity, evidence revision, descriptorId and local token assignments. Never serialize or persist it. A hash may compact evidence or compare payloads; a hash never proves that two native controls are the same control.

## 3. Planner response union

Exactly one discriminator:

| Kind | Required fields | Meaning |
|---|---|---|
| proposal | schemaVersion=1, summary, operations[], expectations[] | One ordered reversible batch; no run ID/permission/target fabrication |
| requestEvidence | queryKind, targetRef?, fields?, cursor? | Bounded request to expand regions, inspect target, inspect item fields or resolve a discovery selector |
| question | question, 2–4 options, reason | Ask about materially different targets/scope; custom answer always allowed |
| cannotComplete | reason, missingCapability? | No effects; offer user recovery without blaming runtime safety on model quality |

One proposal contains 1–64 ordered operations for one customization revision and one DocumentKey. Validate the complete list before activation; a failed operation or mandatory check rolls back the candidate batch, preserving earlier accepted revisions. No nested groups, `required` flags, `dependsOnLabels`, dependency graph or optional-subset execution. If a smaller useful result is wanted, propose it honestly as a separate revision; never silently discard part of the requested batch.

“Effect group” in the remaining design text means this single revision batch, not another orchestration object. A diagnostic groupId, if retained, equals revisionId rather than introducing a separate model-authored identity. Within `insertUI`, unique local node IDs identify nodes created by that operation. Later operations may reference those nodes; forward references to later creators and duplicate IDs are rejected. This is a linear validation pass, not a graph engine. Prepared owned nodes can be created detached before activation; no website mutation occurs during decoding.

`expectations`: effect (`hidden`, `style`, `text`, `ui-inserted`, `canvas-rendered`, `binding-installed`, `projection-visible`, `relocated`), targetRef, property/value or capability-specific outcome. Runtime computes mandatory safety checks independently; model cannot remove them. Aesthetic summary is advisory, not an executable assertion.

## 4. Customization and revisions

### OriginRecord — local persistent source of truth

Required: schemaVersion=2, origin, recordRevision, lastMutationId, customizations[], updatedAt. One record is stored under `rv2:origin:<origin>`. Broker owns serialized writes to this record; content scripts cannot write it. Each write includes the expected recordRevision; stale revisions fail explicitly. `chrome.storage` is not a compare-and-swap database: the guarantee comes from one trusted writer and restart reconciliation, not a fictitious storage transaction API.

### Customization

Required: customizationId, title, enabled, scope, activeRevisionId, revisions[], createdAt, updatedAt, contentSensitivity, grants. Retain active and previous accepted revision initially (2 total); before discarding older history, release session resources and explain undo boundary.

Revision: revisionId, parentRevisionId?, capabilityVersion=1, targetDescriptors[], operations[], savedAt, source (`user-planned` or `imported-reviewed`), providerSummary? (profileId/modelId only), validationSummary. Store validated intent, not rejected model proposal, prompt, provider raw output, inverse DOM or observation journal.

Scope: exact origin plus route predicate. Modes: `exactPath` default; `pathPrefix` with slash boundary; `origin` only after explicit approval. Optional local route discriminators for query/hash apps are in [persistence](13-persistence-and-replay.md). Scope is user-controlled, never inferred solely from “permanently.”

### Runtime-only resources

| Kind | Retained data | Inverse / reconstruction |
|---|---|---|
| CSS aggregate delivery | Exact validated bundle bytes, compositionRevision, contributing logical group IDs, token namespaces, document ID, operation ID, origin | Broker removes exact bundle; disarm affected tokens first; reconstruct aggregate in canonical order on new document |
| Token membership | Element weak reference, prior attribute token state, installed token | Remove owned token only; preserve foreign tokens/site mutations |
| Text edit | Exact Text node reference, siteBaseValue, predecessorValue for provisional replacement, installedValue, ancestor ref | Candidate rollback restores predecessor; disable restores site base, only while node/installed value still match |
| Attribute override | Element ref, name, site-base presence/value, predecessor presence/value, installed value | Compare-and-restore for candidate versus site release; restricted attributes only |
| Owned UI | Direct owned host/root/node refs, local node IDs, local control state, focus-return ref | Remove owned host/listeners only; restore focus if safe; persisted data is validated tree, not DOM |
| Owned Canvas 2D | Versioned viewBox/draw records, accessible fallback, canvas/context/observer refs | Persist validated drawing data only; rebuild/redraw owned canvas; never capture/restore page-owned pixels |
| Event binding | Listener function ref, root, event options, binding ID | Remove exact listener; no serialization of function |
| Relocation | Original live node, site-base parent/sibling/placeholder, predecessor anchors, expected current parent | Failed candidate restores predecessor, disable restores site base if anchors valid; never overwrite framework replacement |
| Projection | Owned UI resources, field-to-source refs, local presentation state | Remove projection; source DOM stays; saved explicit organization may reconstruct |

DOM/resource records are bounded and session-only. Replacement acceptance transfers the original site baseline into the new owner before predecessor ledger release; otherwise disable would restore an earlier Revueon revision instead of the site. Failed inverse resources remain recorded as conflicted until released/disposed, not silently spliced out. A persisted non-secret installation ID identifies owned token namespaces for reinjection cleanup; it grants no security privilege and contains no page content.

## 5. VerificationReport

Fields: verificationId, groupId/revisionId, DocumentKey, Epoch, completedAt, outcome (`pass`, `fail`, `unknown`), checks[], scopeCoverage, baselineRef.

Check: checkId, targetRef/resourceId, metric, before, after, expected, tolerance, outcome, reason. Issue identity is `(checkId, target identity, property/axis)`, not human-readable text or changing measured values. `unknown` has a cause: target vanished, unstable layout, unsupported color, interrupted scan, privacy restriction, hidden document, or API failure. No absent-array-as-pass fallback. Mandatory checks must all pass to accept; advisory aesthetic/evidence checks can remain unknown with explicit UI disclosure.

## 6. ProviderProfile and privacy grants

Profile: profileVersion=1, profileId, label, protocol (`openai-chat` or `anthropic-messages`), exact endpoint URL, modelId, auth configuration reference, capability overrides, context limit, output limit, call timeout, optional cost rates. Capability fields include JSON-schema mode, JSON-object mode, streaming, system-role support and supported token parameter. Unsupported fields are omitted, not guessed from model-name regex.

Credential: local trusted storage only if “remember” selected; session trusted storage otherwise. Never included in profile exports, logs, run payloads to content, or customization revisions. Optional custom headers are named user settings, excluding forbidden hop-by-hop/browser-owned headers. Only the configured endpoint receives them.

UserGrant: grantVersion, grantId, origin, routeScope, capability categories, disclosureVersion, approvedAt, optional expiry. Provider disclosure approval tied to profile endpoint/model-data categories; changing endpoint requires disclosure again. Model-generated booleans named consent are invalid.

## 7. Versioning, compatibility and migrations

- Every persistent/wire root has a schema/protocol version. Unknown major version fails closed; no silent spreading of arbitrary stored objects over defaults.
- Decode → validate bounds → migrate recognized old schema in memory → validate new record → explicit atomic single-record replacement → retain old quarantine until confirmed.
- v0 `rv_<origin+path>` journals are **not automatically replayed by v2**. [Migration](19-migration-and-deletion.md) requires sanitized import as disabled draft with review.
- Derived snapshots/target refs/compiled CSS are not schema migrations; discard and regenerate.
- Missing provider capability means base text response mode; missing operation capability means unsupported proposal, never approximate execution.
- Content compatibility update unloads old runtime before a v2 instance starts; never run both writers on the same document.

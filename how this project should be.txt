# Step 3: Create a "Semantic Page Model"

This is probably one of the most important things you need to build.

Your browser understands the DOM.

Your AI understands meaning.

You need a translator between them.

```text
DOM
 ↓
Semantic Extractor
 ↓
Semantic Page Model
 ↓
AI
```

For example:

```json
{
  "website": "youtube.com",
  "pageType": "video",

  "regions": [

      "id": "sidebar",

      "id": "shorts",

      "label": "YouTube Shorts"
    },
    {
      "id": "comments",
      "role": "discussion",
      "label": "Comments"
    }
  ]
}
```

Now the AI can understand the page.

# Your deterministic runtime

Your file is absolutely right about this:

> The runtime should execute instructions and should not perform reasoning.

Think of the runtime as a machine.

```text
INPUT

{
  operation: "hide",
  target: "sidebar"
}

↓

RUNTIME

↓

Find sidebar
Validate
Apply change
Observe DOM updates
Reapply if necessary
```

The runtime should be predictable.

# The MutationObserver part

A major challenge is this:

You hide something.

Then the website updates.

For example:

```text
YouTube loads
     ↓
Revueon hides Shorts
     ↓
YouTube changes page
     ↓
Shorts appears again
```

So your runtime needs:

```text
Website DOM
     │
     ▼
MutationObserver
     │
     ▼
Detect page changes
     │
     ▼
Check transformations
     │
     ▼
Reapply necessary changes
```

This is how your transformations persist.

Your document already identifies persistent customizations and robust transformations across arbitrary websites as major challenges.

# The hardest problem you have

I want to be very honest.

The hardest part is not:

❌ Building a Chrome extension
❌ Calling an AI model
❌ Changing CSS

The hardest part is:

> **How does the AI say "change this part of this website" in a reliable way?**

Suppose the AI says:

```text
Hide the Shorts section.
```

How does the runtime know exactly what "Shorts section" means?

You need a system like:

```text
Semantic Element
       │
       ▼
Semantic ID
       │
       ▼
DOM Locator
```

For example:

```text
Semantic ID:

youtube.shorts.sidebar

↓

Possible DOM locator:

#items > ytd-guide-entry-renderer
```

But DOM structures change.

So you may need multiple ways of locating something.

---

# A locator could look like this

```json
{
  "element": "shorts",

  "locators": [
    {
      "type": "text",
      "value": "Shorts"
    },
    {
      "type": "aria-label",
      "value": "Shorts"
    },
    {
      "type": "semantic-role",
      "value": "navigation-item"
    }
  ]
}
```

Your runtime tries them safely.
